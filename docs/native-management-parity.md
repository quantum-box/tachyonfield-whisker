# ネイティブ管理画面とWeb管理画面の対応表

比較基準: `quantum-box/tachyonfield` / `73e645adebe3b21dddb83b6d4556ce58b6bee08f` / `apps/client/src/app/navigation.ts`。
アプリの作業基準: `quantum-box/tachyonfield-whisker` / `5c397ff73c66671e88275de7469cc9984380b8c5`。

予約関連は追加でWeb commit `27b3a5296f735b6811bcb9d49b4de615c07ac9e7` と照合済み。詳細は [ネイティブ予約業務](native-reservations.md) を参照。

## 対応範囲と集計方法

Webのトップメニュー113項目に対し、ネイティブの入口と実装範囲を確認した。**113項目すべてに対応する入口はあるが、Webの全画面・全操作と同等ではない。閲覧中心の項目や未実装の複合操作が残る。** 操作欄と差分欄を合わせて提供範囲を判断する。

- 新しい管理カタログは **161画面定義**。同じWebメニューを一覧・設定・操作などに分けたものを含み、Webメニュー **110項目** に対応する。
- 既存専用画面はAgentチャット・思想と行動・現金出納帳・証憑OCRの **4項目**。思想と行動は管理カタログと重なるため、集計で追加するのは **3項目**。`110 + 3 = 113` とし、重複を加算しない。
- `settings/...` のうちWebの113項目に独立した項目がない設定画面は「設定」に集約する。独立項目のAI実行・AI評価はそれぞれの行に残す。ホームの空ルートと `/` は同じ項目と扱う。
- 表の作成時には、コンパイル済みの `management::resources()` から `create`・`edit`・`actions`・`filters` を取得した。在庫・請求書の `decorate` 適用後の定義を使い、builderの書式差や後付け操作を読み落とさない。専用の利益試算・AIチャット・Jobcan取込・書類読取は実装を別途確認して追記した。
- 「閲覧」はAPIから取得した一覧・詳細・明細を表示する範囲。グラフ、帳票保存、関連画面への連続遷移までを自動的に含めない。操作は権限・状態・版・本人条件を満たしたときに表示する。

## 共通の制御

- Webと同じメニュー権限アクション、機能フラグ、提供機能、特定テナント制限を適用する。追加の操作能力・本人条件・レコード状態を確認し、API側の権限制御も継続して使う。
- フォームに明示した項目だけを送信する。関連先は名称で選択し、内部IDを手入力させない。保持すべき既存明細ID・版・未編集項目はアダプターで保全する。
- 金額の最小通貨単位と通常の金額を区別し、十進数文字列・大きい整数を浮動小数点へ変換しない。未取得・未算出とゼロを区別する。
- APIが要求する更新版・更新日時・冪等キーを使う。不明な送信結果を成功扱いせず、同じ内容の再送と内容を変えた再送を区別する。
- ページの読み残し、部分集計、未換算通貨、形式エラーを表示する。テナント切替や新しい詳細取得の後に古いレスポンスを反映しない。
- 写真/PDF/CSVのネイティブファイル選択は現在iOS側の実装。対応する入力・書込の実機検証は別途必要。

契約提供機能はAPIが `enabled` と `resolved` の両方を確定した場合に表示する。Webには提供機能の強制を止める段階移行設定もあるため、その環境ではネイティブの表示条件が厳しくなる場合がある。

## 元メニュー外の既存機能

レジ締めは `screen:register-count` の既存専用画面。Webの当該113メニューには独立項目がないため、上の113項目へ加算しない。現金出納帳設定、レジ設定、印刷などの既存機能も継続する。

## 検証の境界

API契約に沿う入力・金額・版管理・権限のテストに加え、Whiskerのネイティブ描画を記録し、入力・タップ・状態更新を動かすUI回帰テストを追加した。関連選択、明細ID、権限失効、テナント切替、非同期詳細の更新、失敗後の再送、利益試算の入力拒否、分析の正確な数値表示などを対象にする。

これらはネットワーク実アクセスを伴わない。テスト成功は、iOS/Android実機での操作、本番APIとの往復、本番データの変更を検証済みという意味ではない。実行結果と実行できていない確認はPRの検証欄に記録する。
