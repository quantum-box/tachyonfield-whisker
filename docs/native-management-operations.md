# 商品・在庫・仕入・請求・会計のネイティブ対応

この変更は、Web管理画面のREST契約を使うネイティブ画面を追加する。下表の「閲覧」は一覧・検索・明示した詳細項目の表示を意味する。Web側の全操作を移植したという意味ではない。

## 対応した操作

| 商品マスタ | 一覧・詳細、作成、基本項目・価格・公開設定の編集、削除 | バリアント、画像添付、商品別の在庫入出庫 |
| 在庫管理 | 拠点別在庫の閲覧 | ロット明細、入出庫履歴、在庫調整 |

| 期限が近いロット | 基準日時と日数による閲覧 | 期限訂正、訂正履歴 |
| 在庫移動 | 移動記録の閲覧 | 拠点間の移動登録、残高と履歴の再確認 |

## 業務フローと集計の追加対応

以下は `accounting.rs`、`accounting_operations.rs`、`finance_views.rs`、`receipt_pricing.rs` に追加した16画面定義の範囲。既存の領域一覧と合わせて提供する。

| Webメニュー | ネイティブで使える操作 | 残る差分 |
| --- | --- | --- |
| 仕入伝票から単価を記録 | 読み取り済みの仕入伝票を選択、品名・金額・数量・登録済み単価の閲覧。明細ごとに材料・包装規格・パック数または直接の量・税率を指定し、仕入日と訂正金額を確認して記録 | 伝票のアップロード・OCR訂正は既存の専用画面を使用。別画面への自動遷移は未対応 |
| 食品ロスダッシュボード | 期間指定、主要指標、理由・材料・メニュー・カテゴリ・曜日・時間帯の内訳、日別推移、理論と実使用量の差異、集計元と不足件数を閲覧 | グラフ、CSV、集計行から元記録への遷移 |
| 売上・利益ダッシュボード | 日・週・月の集計、顧客・商品・担当者での絞込み、売上・仕入・粗利益・比較、顧客・商品・担当者・仕入先・メニューの内訳、飲食店の原価確認状況と不足情報 | グラフ、CSV、取引元への遷移 |
| 請求・入金の対応一覧 | 送付済み請求、期限超過請求、未回収売掛、Square未照合入金の集約。請求書の宛先と金額を確認した支払案内メールの個別再送 | 一括送信、Square照合、入金消込。請求書の新規発行・送付は別の請求書画面の提供範囲に従う |
| 業務ケース | 期間・拠点・担当・状態での検索、完了条件・未完了事項・履歴の閲覧。引受け、作業権の解放、報告、待機・再開、引継ぎ、完了、失敗記録、取消 | 関連する業務の専用画面への遷移、任意の自動条件の設定 |
| 業務ケースの目視確認 | 業務ごとの手動確認を一覧に展開し、確認済み・未確認を記録 | 承認・計上・精算など、自動で満たされる条件をこの画面から変更する操作は提供しない |
| 業務の進捗集計 | 作業中・完了・失敗・期限超過・担当なし・停滞・定期業務の遅延と未着・手戻り件数の閲覧 | 担当別・拠点別のグラフ、集計から個別条件への遷移 |
| 定期業務 | 作成・編集・有効状態変更・対象期間のケース生成。繰返し、基準日、締切、日ごとの除外曜日、休業期間を指定 | 生成予定のプレビュー、定義削除、既存の完了条件の専用編集。新規作成時は必須の目視確認を1つ設定 |
| 確認依頼・回答 | 未割当・期限超過・担当・状態での検索。自分の引受け、担当者割当、担当者本人による回答、差戻し、取引事実の確認、権限がある人の税務確認、取消 | 新規質問作成、消込候補選択、金額配分、訂正仕訳、詳細履歴 |
| 月次締め | 対象月の集計、貸借、未処理請求・未転記仕訳・未仕訳売上・未照合決済・証憑不足、締め前の対応事項と対象明細を閲覧。理由と確認を伴う締め・再開。会計出力の作成と履歴 | 月次成果物パッケージの作成・別担当者レビュー、顧客への共有・受領、税区分の一括確定、CSV実ファイル保存 |
| 会計運用・営業日 | 拠点ごとの営業日設定と履歴、臨時営業・休業予定の登録。適用日付きの売上集計元設定 | 売上・仕入ファイル取込、既存設定の高度な期間調整 |
| 日次レポート配信 | 拠点・宛先・時刻を指定したメール配信設定作成、停止・再開、メール宛先追加・終了、配信と見送りの履歴、失敗した配信の再試行 | Slack・LINEの資格情報設定、配信名・配信時刻の変更 |

「確認依頼・回答」は入出金明細の事実確認を扱う `/v1/erp/reconciliation/review-requests`。前表の会計問い合わせとは別のAPIで、相互に同じ状態遷移とみなさない。

## データを保つための処理

- 商品編集では取得した `updatedAt` を `expectedUpdatedAt` として送り、バリアント・画像・タグを変更対象に含めない。
- レシピ編集は取得した `revision` を使い、追加オプション・調理手順をフォームに引き継ぐ。材料と仕込み品の重複指定、自己参照、不明なオプション参照、種類の変更を送信前に拒否する。仕込み品の出来高は量と単位を組にし、両方未設定の保存も認める。
- 原価・量・歩留まりなどの十進数は文字列として入力・送信する。発注書・請求書・経費の金額は、指定通貨の通常の金額で入力し、通貨の小数桁に合わせて整数の最小通貨単位に変換する。USDの `123.45` は `12345` として送る。浮動小数点を介さず、発注書と請求書の合計の桁あふれも検出する。
- 経費明細の既存IDは画面に入力欄を設けず、対応する行と一緒に保持する。行の削除後も残った行のIDを取り違えず、新しい行ではIDを送らない。取下げは申請者本人と確認できる場合だけ表示する。
- 新規請求書は下書きとして保存し、送付・SMS・支払いリンク作成は行わない。
- 商品・請求書・経費・食品ロスの作成にはAPIが定義するリクエストキーを付ける。キーの保持と再試行の扱いは共通管理フォームが担当する。
- 在庫領域の変更はサーバーが返す `inventory.manage` の許可があるときに提示する。すべての要求に選択中テナントの認証と境界情報を使い、最終的な権限・状態遷移はサーバーが検証する。
- 仕入伝票の明細位置は非表示の識別情報として保持し、フォームで行を追加・削除できない。選択した行だけを送る前に、税率・材料・数量・金額を検証する。送信直前に元明細を再取得して二重登録を確認し、包装規格が選択した材料に属していることも確認する。税率が未選択の行を8%などに補完しない。
- 食品ロスの未確定値を0にしない。計算できない値、一部除外、除外件数を表示し、比率は十進数文字列のまま百分率に変換する。利益集計の原価不足と未確認状態を表示する。
- 請求対応一覧の一部の取得が失敗した場合は、未取得の領域を明示して取得できた領域を表示する。すべての取得が失敗した場合は空一覧にしない。支払案内の再送前に宛先・金額・通貨・更新日時を再確認し、HTTP応答が成功でもメール配信失敗を成功扱いしない。
- 業務ケースの変更は取得した `version` を `expectedVersion` として送る。完了は有効な本人の作業権・作業中状態・必須条件を確認し、送信直前にも状態を読み直す。手動確認画面から自動承認条件を満たすことはできない。
- 確認依頼はログイン利用者の正本IDを使って引受けと回答者を照合し、送信前に状態・対象版・指紋・回答の変更を確認する。税務確認は専用APIと `accounting.confirmTax` を使う。
- 月次締めでは集計・締め準備・明細の3応答について、会社・年月・期間・状態が同じことを確認する。貸借は桁数を落とさず比較し、対応事項の合計件数も検証する。締め・再開はそれぞれの権限が必要で、実行前に最新状態を取得する。
- 配信の新規登録・再開・宛先追加・再試行は、実際に宛先へ送信される操作として表示する。メール配信の作成は空の対象拠点・空の宛先・重複指定を拒否する。

## 確認した契約

参照したWebクライアントは `quantum-box/tachyonfield` のコミット `73e645adebe3b21dddb83b6d4556ce58b6bee08f`。主に `apps/client/src/features/` 内の各領域のAPI型・入力型・検証スキーマ、ナビゲーション定義、クライアント権限応答を確認した。参照ソースそのものはこの公開リポジトリに含めていない。

ここに記載した閲覧機能の追加だけで、各領域の複合ワークフローが全対応になったとは扱わない。実機での見た目・操作と、テスト用テナントでのAPI往復を確認してから提供範囲を更新する。
